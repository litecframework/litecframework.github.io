liteC brings a simple, compact web development experience to C. Build applications with readable routes, templates, forms, sessions, security features and file uploads.

liteC is designed around concise route declarations and framework helpers rather than repetitive HTTP boilerplate.

Installation

Place the liteC header beside your application source.

myapp/
├── app.c
├── lite-secure.h
└── templates/
    └── index.html

Compile with GCC or Clang:

gcc -std=gnu11 -Wall -Wextra -O2 app.c -o app

Run the application:

./app
The development workflow supports Linux and Android environments such as Termux. Ensure the application can read its templates and write to its upload directory.

Quick start

A basic liteC application:

#include "lite-secure.h"

GET("/") {
    return text("Hello, World!");
}

GET("/about") {
    return text("About liteC");
}

run(8200);

Open http://127.0.0.1:8200 in your browser.

The framework's run() entry point is used in these examples. Follow the current header's required syntax and do not add a separate main() unless the implementation requires it.

Routing

GET routes

Use GET() to declare a route that handles GET requests.

GET("/") {
    return text("Welcome!");
}

GET("/about") {
    return text("About liteC");
}

POST routes

Use POST() for form submissions and other POST requests.

POST("/login") {
    const char *username = form("username");

    return text("Login request received");
}

Dynamic route parameters

Use angle-bracket route segments and retrieve their values with param().

GET("/users/<id>") {
    return text(param("id"));
}

For /users/42, the route parameter id contains 42.

Responses

HelperPurpose
text(...)Return a plain-text response.
html(...)Return an HTML response.
render(...)Render a template with supplied values.
redirect(...)Redirect the client to another location.
GET("/hello") {
    return text("Hello!");
}

GET("/page") {
    return html("<h1>Hello from liteC</h1>");
}

GET("/old") {
    return redirect("/");
}

Use the response helpers rather than manually constructing HTTP response headers for ordinary routes.

Templates

Place HTML templates inside the templates/ directory.

GET("/") {
    return render("index.html");
}

Pass template values

GET("/profile") {
    return render("profile.html",
        "name", "Usman",
        "role", "Developer");
}

Use double curly braces to display values:

<h1>Welcome, {{ name }}</h1>
<p>Role: {{ role }}</p>

Template conditions

The established template syntax includes conditional blocks:

{% if logged_in %}
    <h1>Welcome back!</h1>
{% else %}
    <h1>Please log in</h1>
{% endif %}
Template values support HTML escaping in the established template implementation. Check the current header for the exact escaping behavior and any additional template syntax.

Request data

Form fields

Read submitted form values using form().

POST("/login") {
    const char *username = form("username");
    const char *password = form("password");

    if (!username || !username[0])
        return text("Username required");

    return text("Welcome, %s", username);
}

Query strings

Read URL query parameters using query().

GET("/search") {
    return text("Search: %s", query("q"));
}

For /search?q=liteC, the query value is liteC.

Route parameters

GET("/products/<id>") {
    return text("Product ID: %s", param("id"));
}

Supported form encoding

liteC handles URL-encoded form submissions and multipart request bodies for file uploads.

<form method="POST" action="/login">
    <input name="username">
    <input name="password" type="password">
    <button type="submit">Login</button>
</form>

Sessions

Sessions let an application keep user-specific state between requests.

Set a session value

POST("/login") {
    const char *username = form("username");

    session_set("username", username);

    return redirect("/dashboard");
}

Read a session value

GET("/dashboard") {
    const char *username = session_get("username");

    if (!username)
        return redirect("/login");

    return text("Welcome, %s", username);
}

Session expiry

The expiry form used in the project is:

session_set("username", username, "-e", 600);

This example requests a 600-second expiry.

Clear session data

GET("/logout") {
    session_clear();
    return redirect("/login");
}
The framework has bounded session storage and session-key capacity. Check the current header for the configured limits. Session data is not a replacement for persistent database storage.

CSRF protection

liteC includes CSRF protection for browser-based form submissions.

Automatic HTML form protection

When automatic CSRF protection is active, liteC handles the token integration for ordinary HTML POST forms. Developers do not need to manually create a token field for each form.

<form action="/register" method="POST">
    <input name="username" required>
    <input name="password" type="password" required>
    <button type="submit">Create account</button>
</form>

The framework's HTML integration can provide:

  • A hidden _lite_csrf field in supported POST forms.
  • A lite-csrf-token meta tag for JavaScript requests.
  • Automatic verification before a protected POST route is executed.

JavaScript fetch and AJAX

For JavaScript requests, read the meta token and send it in the X-Lite-CSRF-Token header.

const token = document.querySelector(
    'meta[name="lite-csrf-token"]'
)?.content;

const data = new FormData();
data.append("username", "example");

const response = await fetch("/profile", {
    method: "POST",
    headers: {
        "X-Lite-CSRF-Token": token
    },
    body: data
});
Do not manually set the multipart Content-Type header when sending FormData. The browser must generate its boundary automatically. Also ensure the rendered page actually contains the CSRF meta tag before sending the request.

CSRF behavior

Request typeToken handling
Supported HTML POST formAutomatic hidden token integration.
JavaScript fetch/AJAXSend the token in X-Lite-CSRF-Token.
Multipart uploadSupports the CSRF header alongside multipart form handling.

CSRF is designed to protect browser requests. Developers should check the current header for configuration controls and any manual-verification API before relying on a particular function name.

Rate limiting

liteC provides a route rate-limiting declaration to restrict repeated requests.

RATE_LIMIT("/login", 5, 60);

POST("/login") {
    const char *username = form("username");

    return text("Login request received");
}

In this example, the route is configured for a limit of five requests within a 60-second window.

Example: protect account creation

RATE_LIMIT("/register", 5, 60);

POST("/register") {
    const char *username = form("username");

    return text("Registration request received");
}
Rate limiting is useful for login, registration and other sensitive endpoints. Confirm the current implementation's client-identification method, response status and reset behavior in the header.

File uploads

liteC supports multipart file uploads through upload_save().

HTML upload form

<form action="/upload" method="POST"
      enctype="multipart/form-data">
    <input type="file" name="attachment">
    <button type="submit">Upload</button>
</form>

Save an uploaded file

POST("/upload") {
    int saved = 0;

    if (!upload_save("attachment", saved, "uploads") || !saved)
        return text("Upload failed");

    return text("Upload successful");
}

The arguments are:

  • "attachment" — the HTML file input name.
  • saved — an integer status variable.
  • "uploads" — the destination directory.

Upload metadata

The current application examples use these helpers after saving an upload:

POST("/upload") {
    int saved = 0;

    if (!upload_save("attachment", saved, "uploads") || !saved)
        return text("Upload failed");

    return text("Uploaded: %s (%zu bytes)",
                upload_name(),
                upload_size());
}
HelperPurpose
upload_save(input, status, directory)Save the selected multipart file.
upload_name()Read the uploaded filename.
upload_size()Read the uploaded file size.
upload_ext()Read the uploaded file extension.
Create the destination directory when required and ensure the process can write to it. Never trust the original filename or extension as proof that a file is safe.

Upload validation and security

Applications should validate uploaded files before making them available to users.

Extension and size checks

POST("/upload") {
    int saved = 0;

    if (!upload_save("attachment", saved, "uploads") || !saved)
        return text("Upload failed");

    int valid =
        (!strcmp(upload_ext(), "png") ||
         !strcmp(upload_ext(), "jpg") ||
         !strcmp(upload_ext(), "jpeg")) &&
        upload_size() <= 2 * 1024 * 1024;

    if (!valid)
        return text("Invalid file");

    return text("Upload successful");
}

This example demonstrates checks using the upload metadata helpers. It does not establish that the uploaded file's actual contents match its extension.

Security recommendations

  • Use server-generated filenames where possible.
  • Check file contents and signatures, not only extensions.
  • Limit upload sizes.
  • Prevent uploaded files from being executed as scripts.
  • Keep sensitive uploads outside publicly executable directories.
  • Use CSRF protection for authenticated browser upload requests.
  • Use rate limiting on sensitive routes.

Complete application example

A small example combining routing, templates, forms, sessions, CSRF and rate limiting.

#include "lite-secure.h"

RATE_LIMIT("/login", 5, 60);

GET("/") {
    return render("index.html");
}

GET("/dashboard") {
    const char *username = session_get("username");

    if (!username)
        return redirect("/");

    return render("dashboard.html",
        "username", username);
}

POST("/login") {
    const char *username = form("username");

    if (!username || !username[0])
        return text("Username required");

    session_set("username", username);

    return redirect("/dashboard");
}

POST("/logout") {
    session_clear();
    return redirect("/");
}

run(8200);

Example templates/index.html:

<h1>liteC Login</h1>

<form action="/login" method="POST">
    <input name="username" required
           placeholder="Username">
    <button type="submit">Login</button>
</form>

Example templates/dashboard.html:

<h1>Welcome, {{ username }}</h1>

<form action="/logout" method="POST">
    <button type="submit">Logout</button>
</form>

When automatic CSRF protection is active, supported POST forms receive the required token integration from liteC.

Project conventions

  • Prefer concise GET() and POST() route blocks.
  • Use framework helpers instead of rewriting request parsing manually.
  • Use const char * for read-only strings returned by request and session helpers.
  • Keep templates in the templates/ directory.
  • Use automatic CSRF integration for ordinary HTML forms.
  • Send the CSRF header for JavaScript requests.
  • Use rate limiting for sensitive endpoints.
  • Validate uploaded files before trusting or serving them.
  • Keep optional features optional for application developers.
  • Preserve existing API behavior when adding new functionality.
