Lightweight C web framework

Build web apps.
Keep C simple.

liteC is designed to make building web applications in C straightforward, with compact route declarations and simple helpers for common web tasks.

Installation and setup

liteC is used as a header-based framework in the examples. Put lite.h beside your application source file.

myapp/
├── app.c
├── lite.h
└── templates/
    └── index.html

Compile with GCC or Clang:

gcc -Wall -Wextra -o app app.c

Run the compiled application:

./app
On Android, the project workflow uses Termux. Make sure the compiler is installed and that the application has permission to read templates and write to upload directories.

Quick start

A minimal liteC application:

#include "lite.h"

GET("/") {
    return text("Hello, World!");
}

run(8080);

Open http://localhost:8080 in your browser after starting the app.

Important: run(8080) is the framework entry point in the examples and generates the program entry point. Do not wrap it in your own main().

Routing

GET routes

Use GET() to handle a route that receives a GET request.

GET("/") {
    return text("Welcome!");
}

GET("/about") {
    return text("About liteC");
}

POST routes

Use POST() for form submissions and other POST requests.

POST("/login") {
    return text("Login request received");
}

Dynamic route parameters

Dynamic segments use angle brackets. Read the value with param().

GET("/users/<id>") {
    return text(param("id"));
}

For example, a request to /users/42 makes the id parameter available as "42".

Responses

HelperPurpose
text("...")Return a plain-text response.

GET("/hello") {
    return text("Hello!");
}

GET("/page") {
    return html("<h1>Hello from HTML</h1>");
}

Templates

Place template files in the templates/ directory and render them by filename.

GET("/") {
    return render("index.html");
}

Pass values as key/value pairs:

GET("/profile") {
    return render("profile.html",
        "name", "Usman",
        "role", "Developer");
}

Example template using the established variable-substitution style:

<h1>Welcome, {{ name }}</h1>
<p>Role: {{ role }}</p>
The simple key/value rendering API is established in the examples. Advanced template features such as loops, conditions, escaping rules, and nested layouts are not documented here because their exact syntax has not been confirmed.

Request data: forms, query strings and parameters

Form fields

Read submitted form values with form("field").

POST("/login") {
    const char *username = form("username");
    const char *password = form("password");

    return text(username);
}

form() returns a const char *. Use const char * when storing its result.

Query parameters

Read URL query values with query().

GET("/search") {
    return text(query("q"));
}

For /search?q=liteC, the value of q is liteC.

Missing values

In the established API behavior, missing query() and form() values return an empty string ("").

Sessions

Use sessions to keep simple user state between requests.

Set and read a session

POST("/login") {
    const char *username = form("username");
    session_set("username", username);
    return text("Logged in");
}

GET("/dashboard") {
    const char *username = session_get("username");

    if (!username)
        return text("Please log in");

    return text(username);
}

Session expiry

Pass "-e" followed by the expiry duration in seconds to enable expiry.

session_set("username", username, "-e", 600);

This example sets a 600-second expiry. Omit the expiry arguments for a session without the optional expiry setting.

Clear a session

session_clear();
The agreed API uses session_get(), session_set(), and session_clear(). Do not substitute a different session getter or assume a session_destroy() function exists.

File uploads

Upload forms must use POST and multipart/form-data.

<form action="/upload" method="POST" enctype="multipart/form-data">
    <input type="file" name="avatar">
    <button type="submit">Upload</button>
</form>

Save an uploaded file

The agreed compact call is:

int status;
upload_save("avatar", status, "myfiles/");
  • "avatar" is the HTML file input name.
  • status is a caller-chosen integer variable.
  • "myfiles/" is the destination directory.

Check the status after saving:

if (!status)
    return text("Upload failed!");

return text("Upload successful!");
Create the destination directory and ensure the process can write to it. The exact behavior for missing files, overwrite handling, and directory creation should be confirmed against the current implementation.

Basic upload validation

The current agreed example validates the file extension and size, then removes a file that fails validation.

#include "lite.h"

GET("/") {
    return render("index.html");
}

POST("/upload") {
    int status;

    upload_save("avatar", status, "myfiles/");

    if (!status)
        return render("result.html", "message", "Upload failed!");

    int valid =
        (!strcmp(upload_ext(), "png") ||
         !strcmp(upload_ext(), "jpg") ||
         !strcmp(upload_ext(), "jpeg")) &&
        upload_size() <= 2 * 1024 * 1024;

    if (!valid) {
        char path[512];
        snprintf(path, sizeof(path), "myfiles/%s", upload_name());
        remove(path);

        return render("result.html",
            "message", "Invalid file! PNG or JPG, maximum 2 MB.");
    }

    return render("result.html",
        "message", "File uploaded successfully!");
}

run(8080);
Validation order: this example saves first, validates second, and removes the rejected file. It reflects the existing example, but a safer future implementation would validate the temporary upload before moving it into the final destination.

Security note: extension checks and client-provided MIME types do not prove the file's real content. For production use, verify file signatures/content, generate safe server-side filenames, prevent path traversal, and store uploads outside executable web directories where possible.

Complete small example

A minimal login-style form flow using the established route, form, session and template APIs:

#include "lite.h"

GET("/") {
    return render("index.html");
}

POST("/login") {
    const char *username = form("username");

    if (!username[0])
        return text("Enter your username");

    session_set("username", username);
    return text("Welcome!");
}

GET("/dashboard") {
    const char *username = session_get("username");

    if (!username)
        return text("Please log in");

    return render("dashboard.html", "username", username);
}

GET("/logout") {
    session_clear();
    return text("Logged out");
}

run(8080);

Example templates/index.html:

<form action="/login" method="POST">
    <input name="username" placeholder="Username">
    <button type="submit">Log in</button>
</form>

Example templates/dashboard.html:

<h1>Welcome, {{ username }}</h1>
<a href="/logout">Log out</a>

Project conventions

  • Keep application code short and readable.
  • Use const char * for values returned by form() and other read-only string helpers.
  • Use GET() and POST() route blocks rather than verbose handler boilerplate.
  • Use run(port) as the application entry point in the examples.
  • Keep optional behavior optional; do not force pointer-heavy syntax on the application author where the framework can provide a simpler API.
  • Preserve existing API behavior when adding new helpers.
